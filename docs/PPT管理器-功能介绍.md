# 启幕（暂定名）· PPT 管理器 — 全面功能介绍

> 产品定位：**面向大公司的 PPT 管理器**。它管的不是一个个 PPT 文件，而是公司全部演示内容本身：内容按话题拆开、留版本、按索引组成成稿，导出后还能持续更新。本文档汇总已定功能；标注“待审定”的是尚需拍板的事项，标注“建议”的是设计方补充、尚未纳入规格的功能。

## 一、它解决什么问题

- 同一份内容（如公司介绍）在无数 PPT 里各存一份，改一处要满世界找文件
- 稿子发给同事后就失控：你更新了，对方手里还是旧版
- 同一话题有精简版、详细版、中文、英文、给不同客户的不同说法，没人说得清该用哪一版
- 谁能看哪些材料没有边界：技术资料和对外介绍混在一起随便流传

它的答案是：**内容只有一份源头（在服务器上），PPT 文件只是按索引临时组装出的交付物；交付出去的文件仍与源头相连，源头一变，文件打开时就收到更新，并能在原文件里原地换页。**

## 二、系统组成

| 组成 | 形态 | 职责 |
|---|---|---|
| 服务端 | Rust 服务，跑在局域网常开电脑 / NAS | 存全部内容、版本、索引、账号与权限；校验权限；下发更新；生成导出 |
| 客户端 | Rust 桌面程序（GUI）+ 同步交付的 CLI | 浏览、组装、导出、发布、组织管理；CLI 供 AI 全量接管与自动化 |
| PowerPoint 侧 | 客户端内置的 COM 桥（一期）；加载项（二期） | 在打开的文稿里提示更新、原地换页、插页、发布 |
| 核心库 | Rust 库，GUI / CLI / 服务端共用 | 版本、索引解析、组装、导出、权限、更新比对的唯一实现 |

### 架构审定结论（已定）：一期两件套，插件二期

原设计是“本地程序 + 服务器 + 插件”。评估后已审定：**一期只做两件套**——原地替换的本质是操纵 PowerPoint 里正打开的那份文稿，在 Windows 上独立程序经 COM 自动化从外部连接正在运行的 PowerPoint，同样能插页、删页、导出页；而且免去给每台机器部署加载项、处理信任中心，适用的 PowerPoint 版本面也更宽（不依赖较新的 Office JS 接口集）。独立插件多买到的是三样：PowerPoint 内的任务窗格体验、文件打开瞬间的事件级提示、Mac / WPS 等没有 COM 的环境——这些放到二期：PowerPoint 操作层做成独立适配层（桥），二期按同一接口补真正的加载项（含 WPS）。

### 界面设计原则（已定）：现代化、克制、简洁——只针对产品页面

先分清两个层面：**设计文档要详细**（本介绍与规格把规则、边界、例外、验收写全，不压缩）；**产品页面要极简**。客户端所有页面与对话框执行：页面里不写功能说明书——没有解释性段落、规则说明、操作教程和大段副标题；只留标题、缩略图、对象名、状态徽标、版本号 / 页数等关键数字、维护人与时间小字、短按钮，卡片最多一行简介，分区头只有标题、数量和动作。需要解释的内容按需出现（tooltip、帮助入口、首次引导、点开后的详情层）；确认与报错只给一句结论加必要动作。视觉上同样克制：现代视觉语言、统一间距与层级、少色彩阴影装饰、少控件堆叠、留白充足、图形优先，不做老式拥挤的界面。按钮等控件默认**紧凑小尺寸**，页面面积优先留给封面、缩略图与文字说明，按钮不与内容争空间。但极简不删关键状态、风险确认和必要操作。目标是：看图即懂，点开再看细节。**卡片全产品只有一张标准卡片**：封面、标题、必要信息、状态徽标、维护人与时间的版式到处一致，所有页面都调用这一张，特殊信息只走徽标和一行小字；卡上只留认得出、做得了决定必需的文字（一行简介封顶），详细介绍、历史记录和次级操作都放进双击打开的详情里——卡片负责扫视定位，详情负责看全。**主要页面不用弹窗**：详情、编辑、合并裁决、换版本这些主要工作面都是整页打开、页内进入；弹窗只留给删除确认这类一句结论的小确认。

## 三、核心概念（先看懂这六个词，后面都好懂）

- **内容位**：一个话题位置，如“合作伙伴介绍”“公司历史沿革”。身份稳定，不随页数变
- **呈现形态**：同一份内容的一种呈现 = 形态（精简 / 详细）× 语言（中 / 英 / 日）。精简与详细同属一条内容线，由**分拆**（一页展开成三页）或**合并**（三页浓缩成一页）产生，可在同一位置相互替换
- **版本**：每种形态各自的不可变历史，用**语义版本号 X.Y.Z** 标记（如 1.1.1 … 10.0.5，全系统统一，索引的发布标签同制）。记录页片段、缩略图、文字、所依据的内容修订、来源（直接编辑 / 分拆自 / 合并自），并正式记录**修订时间**（精确到分钟，版本详情里与作者、改动说明并列）。发布时不用手写号码：在确认卡上点选**大版本 / 小版本 / 文字调整**三段之一，系统按所点段递增生成新号；并且会按变更智能预选——页数 / 形态变化或内容大改预选大版本，数据、说法更新预选小版本，仅错别字、排版微调预选文字调整，发布人可改选，选了什么都留痕
- **版本线可拖拽重排（编号顺移、身份不变）**：内容块的历史版本区里，可以把一张新版本卡直接**拖到历史序列的任意位置**——拖到中间它就是历史版，拖到最前它就是最新版。落下的位置决定它的号码：以它前一版为基、按你选的递增段（大 / 小 / 文字调整）算号，它后面的版本则依次**级联顺移编号**（如在 2.3.1 与 2.4.0 间以小版本插入，新版是 2.4.0，原 2.4.0 自动变 2.5.0，往后同理），整条线始终单调递增。号码能变是因为每个版本另有**不变的内部 ID**：索引锁定、快照、已导出 PPT、导出记录全按 ID 认版，改号不伤任何引用，老 PPT 打开时显示新号、老导出记录保留当时号码可对照；每次改号逐版留痕，在版本详情的“编号变更记录”里可查。索引的发布标签（tag）不适用此条——标签不可变
- **内容修订**：内容本身的变更轴（事实、数据变了才递增）。某形态依据的修订落后 → 标“内容已过期”
- **语言绑定**：同一页的中 / 英 / 日形态显式成组对应（含多页时的页级对齐），是整稿换语言、AI 翻译与双语页的基础
- **内容块层级**：块分三级——元素块（页内一个文本框 / 图片 / 二维码块）、页块（一整页）、组块（有序多页）；内容位就是被版本化管理的页块 / 组块，索引是组块之上的整稿组合。两个块的内容可合成为一个**新块**（独立成线、记派生来源，见功能 6 与规格 3.15）
- **索引文稿（成稿）**：一份整体文稿在系统里的存在形式——不是 PPT 文件，而是一串有序引用（内容位 + 形态 + 跟随最新 / 锁定版本）。浏览与导出时才解析成页。**索引就是一个 Git 式仓库**：坐落在它的目录坐标上（所属文件夹完整路径，常驻不消失）；每次编辑是一个**提交（commit）**，历史是提交图；在提交上打**标签（tag）**就是发布版本（V1.0、V3.5.4…，不可变）；从任意提交 / 标签拉**分支（branch）**做变体（如展会版、西门子定制），主分支 main 是成稿线，分支还能**合并**回目标分支（冲突逐条人工裁决）；要整份另起炉灶则“复制为新索引”（新仓库）。导出的 PPT 绑定（仓库、分支、快照）三元组，只沿自己跟踪的分支收更新，互不串扰；索引可转历史（原称过期：不再新导出，存量稿收到一次迁移通知）/ 作废或删除
- **分组（目录）**：左侧目录树，一级是用途（如“公司介绍”），可建子文件夹；同时是权限划分单位

## 四、功能全景

### 1. 内容库与目录树（客户端主界面）

- **内容页只做内容维护**：左侧目录树（一级目录按用途分：公司介绍 / 公司技术 / 公司案例…，可建子文件夹；每个成员只看到自己有权看的目录）；主窗口就是左右两栏——**左 = 目录，右 = 该目录下的内容块维护区**：平铺全部内容块的最新页，双击进入内容块维护（形态 / 版本、发布、标签、讲稿、语言绑定、附件、嵌套子块、撤回、申请公开）。内容页**没有组装和导出**——组装一份新 PPT 去索引页的组装工作台（见功能 2）
- 内容以缩略图卡片呈现，带标签、适用说明、过期标记；可按语言、标签过滤，按标题与页面文字搜索；单击选定只服务于维护操作，双击打开即下钻维护
- **我维护的只用绿框标，不另设板块**：内容页里没有「我的维护」专区——你维护的内容块就在原目录位置，卡片多一圈绿色外框线，一眼认出（和演示厅的绿框同义）。你提交审核**被驳回**的版本不会出现在公司的正式内容里、同事看不见；只有你自己的内容页里还留着它，卡片换成**红 / 粉色标示**并挂「已驳回」标，双击打开能看到驳回理由，改好重新提交

### 2. 选页与组装（在索引页的组装工作台里做一份新 PPT）

- 组装发生在**索引页的组装工作台**：新建组装 / 新建索引时进入，用它的**内容选用器**选页（选用器复用内容浏览的组件、处于选用模式，但不是内容页）；组装成果存为索引或个人组装记录，导出也只从索引页（及演示厅既有入口）发起
- **快捷选**：在选用器里单击卡片即选入，选的就是卡片显示的最新版
- **打开选**：双击某个内容位（如“历史沿革”），并列它的一页版、三页版及各版历史，任选其一；选了三页版默认三页全选，也可只勾其中一两页（摘选页单独记绑定，源头更新时按页提示）
- **优选推荐**：选了开头页后，系统按主索引（官方成稿）的序列推荐接下来该选的几页，可一键按成稿补齐；索引采用的候选标“优选”；再叠加历史组装的共现推荐。推荐自动避开无权分组与其他客户的专属页
- 组装清单里拖动排序、实时预览整稿与总页数；选模板（定尺寸 / 母版 / 主题）后导出
- 临时组装可存为索引文稿，长期复用

### 3. 导出与文件管理（导出即最新）

- 索引文稿在客户端点开即可浏览（解析到最新版），满意点导出即生成 PPT——**导出的永远是导出那一刻的最新版**，不需要先去“更新系统里的那份文件”，因为系统里根本没有那份文件，只有索引
- 每次导出生成一条**导出记录**（谁、何时、所属索引版本、各页的版本快照），可查、可对比、可从索引再导一份新的
- **索引像 git 一样工作**（索引是这个产品的核心，设计只认四条：结构合理、界面现代化、操作易上手、关系易理解）：日常编辑是一个个**提交**（带作者、时间、说明与条目 diff，历史是提交图，不是流水号）；在提交上打**标签**（V1.2、V2.0…，不可变）发布后，跟踪对应分支的已分发 PPT 才收到结构更新——改稿过程不打扰同事。从任意提交 / 标签可拉**分支**做变体，分支图直接回答“哪条分支从哪分叉、分叉后各走了多远”；分支可**合并**回目标分支：单边改动自动合入，同一条目双边都改的逐条人工裁决（用我的 / 用对方的 / 手动选形态与版本策略），合并留下一个合并提交。整份另起炉灶用“复制为新索引”（新仓库、新坐标，记明复制自谁 @ 哪个标签）。索引可转历史（原称过期，存量稿收到一次迁移通知）/ 作废 / 删除（软删留档）
- **索引总览（先选索引，再编辑）**：索引页的骨架与卡片组件仍与演示厅一致，但组织方式按索引自己的两条坐标来：左侧目录树常驻，总览默认打开就是**“使用中”档**——状态筛选固定三档、顺序不动：**使用中（默认）→ 历史 → 全部（排在最后）**，默认不把历史索引混进来。右侧默认**按目录分组**陈列（分组标题就是文件夹完整路径，**份数只数使用中的**，主索引在本组排第一），还可切换到**按派生关系**视图看仓库分支图（切换控件在右侧内容区顶部工具行的右端，与左侧目录树分开，只管右边这块内容）。每个目录分组头在“公司介绍（2 份索引）”后面还有一个**“历史（N）”按钮**：点开就在本组里并列加载出该目录的历史索引（带“历史”徽标、画面降权），再点收起，不用切整页筛选。卡面已经再简化：只留封面（取这份索引的第一页整图，不再拼图）、标题、当前发布标签、状态徽标与维护人 / 时间小字（外加表示公开范围的边框颜色和主索引徽标）——目录坐标、谱系、条目数都撤下卡面：坐标看分组标题（就是完整路径），其余双击进详情看。单击只选定，可预览成稿、导出、分享、推送到演示厅、拉分支或新建索引；双击或点“打开编辑”才进入详情。**中文语境下总览只列中文索引**：英文对应索引不在总览出现、卡上也没有对应徽标，打开详情后才在「派生关系」视图顶部看到它——语言对应是另一个仓库的镜像，不是分支，不进分支图
- **派生关系只在详情里看**：总览卡上不再放派生结构按钮和页面底部的预览坞（先前设计过悬停速览，已撤下）——双击打开索引，详情里的「派生关系」视图就是分支图，当前索引在图中高亮，来路与下游都看得清
- **把做好的索引推送到演示厅**：索引详情和总览卡上都有“推送到演示厅”。推送按主线（main）当前已发布的最新版本走——还没发布过版本的索引会提示先发布，不能推。推送后进入演示厅广场的**上架审核队列**，和成员自荐是同一个队列、同一套审批（待审 / 通过 / 驳回；驳回必须写理由）。通过后，这份索引就在广场上架展示，条目标明来源索引和它的目录坐标，之后来源索引发布新版本，广场上的展示自动跟着解析到新版本，不用重推；被驳回的，索引详情里能看到驳回理由，改好后可以重新推送。来源索引日后转历史或作废，广场条目会标明来源状态，不会悄悄消失。推送只是多了一个展示出口，不影响这份索引原来的更新线和已导出的 PPT
- **我维护的索引也在总览里，样式不特殊**：和大家的索引同一款卡片。已经公开的（不管是谁维护的）和大家的混排在主区；我维护但还没公开的——没申请、审批中、被驳回待改——沉到总览最下方的「**我的未公开**」区，带状态小标，这个区只有我自己看得见。卡片**边框颜色表示公开范围**：全公司 = 蓝、上级组织 = 紫、本部门及子部门 = 绿、仅本部门 = 橙、未公开 = 灰；总览工具行有个小图例，索引详情里也标着公开范围和同色圆点，改投范围后边框跟着变色
- **索引详情 = 内容块图墙**：双击打开索引，页眉很干净——第一行是「返回索引总览」和视图切换按钮（同一行），第二行是标题，标题正下方一排动作按钮（推送到演示厅 / 发布新版本 / 拉分支 / 发起合并）；页眉之下，全部条目以图形卡排列——每卡是该内容块当前解析版本的整组页面缩略图、块名、形态 / 语言与跟随最新 / 锁定徽标，一眼看全这份索引由哪些块组成。图墙上有四个结构操作：**拖动卡片调顺序**（拖拽中有落点指示，松手自动记一个排序提交）；**双击条目卡就地换内容**——图形化列出同一内容块的其他形态与版本，选某形态最新版则条目跟随最新，选历史版则自动转为锁定版本并在卡上标明，多页形态还能只摘其中几页（摘页绑定），替换同样生成提交；**条目之间点插入点加新块**——相邻卡片之间（和首尾）有插入点，点开选用器选一个内容块放进来，生成“新增条目”提交；**全面编辑重选页**——点条目卡上的“全面编辑”，跳到内容页并直接打开这个内容块（顶部有一条“为索引 X 选页 · 确认返回”的上下文条），在那里重新勾选这个条目到底用该块的哪几页，确认后回到索引详情生效。内容页平时仍只做维护，这个选页模式只在从索引跳过去时出现。详情页顶部有一排小按钮**切换视图（条目图墙 / 提交图 / 历史版本 / 导出记录 / 派生关系）**，一次只显示一个区、默认停在图墙，不再把所有区块纵向堆满；切到「派生关系」看到的是本仓库的分支图，**当前这份索引在图中高亮**（带“当前”小标），从根到它的分叉路径也一并强调，一眼看清自己在谱系里的位置；移动文件夹、改生命周期、删除等低频动作收进「更多」菜单。**条目下方带快速换版带**：摆出这个内容块最近的几个历史版本（从新到旧），点哪一版就直接把条目换成哪一版；带头还有一个「保持最新」按钮，点一下条目就回到跟随最新；「更换版本」入口排在「去内容页维护」前面
- **条目锁定 = 钉死不动**：条目要么跟随最新，要么固定（锁定）在某个版本——可以把当前版本固定下来，也可以在换内容时选一个历史版本并锁定。锁定之后，这个内容块再出新版，索引预览、导出、已导出 PPT 的更新检查都纹丝不动、连提示都不弹，卡上只留一句弱提示“源内容块已出新版 vX（已锁定不跟随）”；只有维护人手动更换版本或解除锁定才会变。导出前体检里锁定条目算已知项，不当警告
- **索引版本带与老页面**：索引详情切到「历史版本」视图时有一条**版本带**，把这条分支发布过的版本（标签）从新到旧图形化排开（与内容块历史版本同款）。点开任一版本，进入当时那一版的**只读老页面**——整面图墙冻结在那个时刻的条目、顺序与各条目版本，顶部标明“历史版本 V__ · 只读”，还能一键导出当时的整稿（导出记录会记明来源标签）。老页面里若某个内容块的原版本已经被删除，不留空洞：自动以同一内容块、同一形态的下一个存续版本替代展示，卡上标明“原版已删 · 以 X.Y.Z 替代”，导出记录里同样可查——这条替代规则对锁定版本被删等一切“引用版本不存在”的场合通用
- 导出文件内嵌清单并在服务端登记，之后它就是一份受管理文稿（见第 4 项）
- 导出时可勾选“同时导出附件”，把配套 Word / PDF 一并落地

### 4. 更新分发（这个产品的核心）

同事装有客户端 / 插件时，分发出去的导出稿这样保持最新：

- **打开检查**：在 PowerPoint 里打开文稿，自动比对并给出更新清单，分两类不混淆——“有更新”（同形态新版本，或内容已过期）与“可替换形态”（同话题的精简 / 详细等其他形态）
- **逐条审阅或全量接受**：每条可先预览（缩略图、文字差异）再决定；也可以一键全量更新
- **原地替换（硬性要求）**：接受后就在当前打开的原文件里删旧页、插新页，还是原文件、原路径；不生成“更新好的新 PPT”；不自动保存，由使用人检查后保存
- **页数变化同理**：一页变三页、两页变一页，都是原地删 N 插 M，整稿页数随之增减，后面的页靠绑定 ID 定位不乱
- **结构更新（按索引比对）**：导出稿记有来源索引与导出时的索引修订。作者在索引层面新增一个模块、删掉一个不要的模块，同事打开副本时会分别收到“新增模块”（在相邻位置插入）和“删除模块”（删掉那几页）的提示，与内容更新在同一份清单里
- **护栏**：本地改过的页有新版时明确三选一（用新版 / 保留本地 / 先预览），不静默覆盖；要删的页被本地改过则默认不删、须单独确认；跳过的变更在同一次索引修订内不再反复打扰
- **回退**：任何内容位可切回任一旧版本，走同一原地流程

### 5. 继续插页（导出之后不脱管）

- 文件在 PowerPoint 里打开时，用插件 / 桥的页库面板把当初没选的页插进来（指定当前页前 / 后），绑定与组装记录同步回服务端
- 文件没打开时，在客户端改它的组装清单再落盘；若文件正被 PowerPoint 打开，客户端会让路并提示走 PowerPoint 侧入口
- 本地新做的页还不在库里时，可直接“导入页库并登记”：指定内容位与形态、发布，从此受管理

### 6. 发布与版本管理（作者侧）

- **整稿导入工作台**：一份做好的 PPT 导入时，AI 自动划板块（按分隔页、标题、话题相似度），逐块给出处置：与库中一致的关联掉、像已有内容位新内容的建议为其新版本、**全新的自动新建内容位并起好名字、写好描述**、给出建议目录；导入人在工作台里确认四件归属（目录 / 内容位 / 形态与语言 / 维护人），可拖动改分界、并块拆块；有审阅与快速（高置信自动入库、可整批撤销）两种模式。导入完成会产出一份带清单的纳管版文件；同一稿再导入时只审变化的块
- 在客户端导入整份 PPTX，或在 PowerPoint 里选中页直接发布；把页指认到内容位 + 形态，系统按指纹只收真正变了的
- **点开即改（编辑回路）**：在内容块详情点“编辑”，片段会用外部编辑器打开（PowerPoint / WPS / DeckCraft，默认哪个自己设），改完保存、回客户端点“更新”即发布新版本，当前页面立刻刷新成新版；把 Craft 编辑器直接内嵌进客户端是二期深化，一期先用调用，体验链路已经闭环
- **复制粘贴发布**：在 PowerPoint 里复制一页 / 多页，切到客户端选中内容块粘贴，确认一张预填好的卡即发布为该形态的新版本，且**自动成为最新版**（版本号最大即最新，全系统无“手工设为最新”这一步）；剪贴板取不到片段时自动改走 COM 桥取 PowerPoint 当前选中页
- 发布时声明：是否含内容实质变更（决定内容修订是否递增）、来源（直接编辑 / 分拆自 / 合并自）
- 草稿与发布分离：可先仅本地存草稿，再决定发布到服务器；并发发布有冲突提示，历史从不改写
- 某形态内容过期时，发布者界面有明确提醒（依据 r4、最新 r5），按新修订更新后标记自动解除
- **跨块合成**：两个（或多个）块的内容可合到一页、生成一个新内容位（新块）——新块独立版本、记派生来源；来源后来更新时新块标“来源已更新”，可一键重新合成出草稿再定版；合成时专属标签按最严继承、防洗白（规格 3.15，设计提案待审阅）

### 7. 讲稿与自动备注

- 每一页都可备好“介绍时要说的话”：人工逐页写，或让 AI 按页面内容起草（附讲解时长估计）再改定；原稿自带的 PowerPoint 备注在导入时会被读入，不丢
- 讲稿随版本走、按语言各备一份（AI 翻译时连讲稿一并翻）；只改讲稿不惊动已分发的稿子，下次该页更新时顺带同步
- **导出开关**：导出时可选“添加备注”——开则讲稿自动写进每页的演讲者备注，拿到的是能照着讲的讲者版（缺讲稿的页会在报告里点名）；关则导出干净稿，适合直接发客户
- 讲稿还能一键汇成一份提词文档（Word / Markdown）打印使用

### 8. 标签与适用说明

- 任何成员可给**版本**打标签——主要是**客户**（如西门子；另有“通用”）与**场合**（详细业务介绍 / 简要介绍 / 内部汇报…）两个受控维度（词表由管理员维护）加自由标签；同页不同版本可有完全不同的标签
- 客户标签分“适用”与“专属”（含该客户名称 / Logo / 数据）：组装与插页时把别家专属页插进本客户稿子会弹警告确认
- 标签参与三处：页库筛选与推荐排序、更新匹配（西门子的专属新版只提示西门子上下文的文稿）、组装上下文（先定客户 + 场合，对的页排前面）
- 每个版本可写一句**适用说明**（“这版适合给西门子做详细业务介绍时用”），显示在卡片与版本列表里

### 9. 组织、部门与权限

- 按大公司形态建模：**公司 > 部门（树形，可多层）> 成员账号**；账号由管理员开设（密码哈希存储），可兼属多部门；停用即刻失效，其发布的历史版本保留署名
- 系统角色：超级管理员、部门管理员、普通成员
- **分组即权限单位**：按“分组 × 能力（查看 / 使用导出 / 发布 / 管理）”把权限授给部门（默认向子部门继承）或个人。例如：管理层看全部三个分组；技术员工只授“公司技术”；普通支援人员只授“公司简介”
- **服务端逐请求强制**：页库、搜索（含计数）、缩略图与片段下载、更新查询与下发、导出生成、发布，全部按账号过滤——无权的分组连“存在”都不泄露。登录、导出、发布、授权变更都记审计日志
- **成员自维护与申请公开（高级功能，默认关闭）**：管理员可按组织节点开启并继承到子部门。开启后，普通成员只能在“我的维护”里维护本人上传 / 创建且本人担任维护人的页面、个人索引和演示厅条目，不能因此改动他人的正式内容或整个分组；维护好后选择本部门、含子部门、上级组织或全公司等公开范围提交申请，由目标范围的组织管理员审批，通过后直接进入正式内容页 / 索引页 / 演示厅，驳回须写原因、可改后重提。设置也可切为**免审公开**，选定范围后立即公开，但仍留记录、通知管理员，管理员可下架。已公开内容的实质更新先形成待审新版本，旧版继续生效；演示厅“自荐”就是同一套申请公开流程
- **导航与设置分级**：顶层页签顺序固定为 **演示厅 → 内容页 → 索引页 → 设置**，软件打开默认落在演示厅；组织管理不在顶层，进**设置**页里办。设置页按身份变脸：超级管理员看全部（公司级全局项、完整组织树与全部节点的组织管理、全部审批队列）；部门管理员只管本人部门及子部门那棵子树（组织维护、成员归属、本范围授权与审批），公司级全局项只读、标明由超级管理员维护；普通成员只有个人设置（个人资料、我的离线缓存开关与容量、个人偏好），看不到任何组织管理区
- **个人资料不止微信，公司还有一套公共资料**：对外资料除姓名、职务、电话、邮箱、微信二维码外，还可填领英、X、Facebook、Instagram、YouTube、TikTok、微博等社交账号（链接或二维码），封面 / 尾页的占位符都能引用。另有一套**公司公共资料**——公司电话、公众号名称与二维码、官网、地址等公司级信息——由超级管理员维护，也可以指定一名成员当「公司资料管理员」代为维护（只管这一摊，不带其他管理员权限）。导出时多一个选择：**个人版**（默认，按归属人资料填）或**公用版本**——选公用版，封面 / 尾页的联系区直接带入公司电话、公众号二维码等公司信息，不带任何个人信息

### 10. 附件（介绍材料）

- 可给索引文稿或内容位挂配套材料：Word、PDF 为主，任意文件可传；记文件名、大小、上传人、时间与说明
- 客户端内列出与下载，PDF 可内预览，Word 用本机程序打开；导出 PPT 时可勾选连附件一并导出
- 附件跟随挂载对象的分组权限；**只在 Rust 程序（客户端 / CLI）里有，插件不做**（按需求方指示）

### 11. 搜索

- 按标题、页面提取文字、标签、内容位搜索；结果先按账号权限过滤
- 版本间文字差异对比，辅助审阅更新

### 12. 多语言：绑定、AI 翻译与双语页

- **语言绑定（就在打开的内容块里绑，没有单独的绑定页）**：同一页的中 / 英 / 日等版本显式绑定成组。打开一个内容块（如封面），在当前版本的页面缩略图上就能选目标语言、绑到那个语言的对应页——英语、日语、双语都在可选之列；公司到底启用哪几种语言，在**设置里维护一份语言清单**，可增删。内容位详情里并列展示、缺译一眼可见；多页形态有页级对齐（页数不同可手工指定对应关系）；语言版本当初被分开导入的，可“补绑定”合并成一条内容线
- **整稿换语言**：一份稿子（或单个话题）可按绑定关系一键原地换成另一语言的最新版；没有对应语言的列入缺译清单并原样保留。同一索引换语言上下文即可导出英文版、日文版
- **译文待更新**：主语言内容更新而译文还没跟上时自动标记，出现在发布者待办
- **AI 翻译**：接入 AI 把每一页逐框翻译成多语言，保留版式只换文字，产物是**草稿**——必须人工逐页校对后才能发布；带公司术语库与不译名单保证译法统一，译文过长可能溢出的文本框会标红；源头更新后只增量重译变化的页。整份索引可批量翻译（CLI 也支持）。这是系统唯一需要外网的功能，可单独开关
- **双语页**：有的场合要一页同载两种语言（中英对照等）——双语是一种正式形态，与单语形态并列可选、同样原地替换；可由绑定的两种单语形态按上下 / 左右对照模板辅助生成草稿（缺一种语言先 AI 补译），任一来源更新时双语页标“待同步”

### 13. 与 DeckCraft 兼容

- 在 DeckCraft 里做的 .pptx 与 PowerPoint 做的同权导入管理；本系统导出的 .pptx 能在 DeckCraft 中正常打开编辑
- 文稿内嵌清单须经得起 DeckCraft“打开—另存”往返（POC 实测项）
- 底层复用其 Rust 资产：deckcraft-pptx（PPTX 导入导出）、render（缩略图）、egui 界面壳、craft-update（局域网镜像分发客户端更新）、craft-i18n（界面多语言机制）

### 14. CLI 与 AI 全量接管

- 全部功能同步提供 CLI，与 GUI 共用同一核心库，功能等价：导入、发布、标签、索引编辑、组装、导出、查更新、组织与权限管理、服务端运维，一件不少（索引命令按 Git 心智组织：log / branch / tag / diff / merge / checkout 的语义映射为 JSON 命令；组装 / 导出命令归索引域，内容域命令只含维护操作，与页面职责一致）
- 为 AI 设计：全非交互；`--json` 结构化输入输出；稳定 ID 与错误码 / 退出码；`--dry-run` 预演变更；尽量幂等
- CLI 以账号身份登录，照样受分组权限约束——是“把某账号能做的全部开放给 AI”，不是后门
- 兼作验收与回归的自动化工具：整条业务链可写成脚本反复重跑

### 15. 部署与运维

- 服务端跑局域网常开电脑 / NAS；数据是一个可整体搬移的目录（SQLite + 文件），开发期跑在开发机，上线拷过去改地址即可
- 局域网发现（mDNS）+ 手动地址双通道；客户端新版本由主机作镜像分发、自动更新
- 主机管理：成员与设备确认、数据备份导出、操作日志

### 16. 演示厅（成品广场、指定分享与我的库）

- 工作区之外再设一个面向“拿现成稿去展示”的板块，定名**演示厅**（不叫成品）：里面流通的是可直接对外展示的完整稿——来自某索引的发布版本或一份个人组装，带封面图、标题、一句介绍与标签，并标注**维护人是谁、最近谁修改过**（历史可展开）
- **广场**：组织范围陈列区，管理员选品上架、排序、写推荐语；成员**自荐**就是把本人演示厅条目按“成员自维护与申请公开”提交公开，须先由管理员开启该高级功能，再按所选组织范围审批或免审上架，未开启时只有管理员选品上架。索引维护人把索引**“推送到演示厅”**也进同一个审核队列、走同一套审批：通过后在广场上架，条目标注来源索引与目录坐标，并跟随来源索引的新发布版本更新（见功能 3）
- **指定分享**：不进广场也能分享，对象可以是成品条目、也可以是一份索引直接分享；目标三类、落点不同——**个人**：对方点“保存”才收进自己库里自选的目录，不强塞；**部门**（按公司架构的部门树）：部门成员人人在“收到的分享”里见到、各自保存，新加入该部门的人也能看到；**群组**（自建协作组，见规格 7.7）：直接进入群组的共享空间，全体成员打开群组即可见可用，可再保存进自己的库
- **我的库**：每人一套个人目录（左目录右内容，与内容页同版式）。新账号按管理员的“新人基础模板”初始化——基础目录 + 官方推荐预置；之后完全归个人自由增删改组。从广场拉入、收下分享，都是**引用**不是拷贝：源头更新照样跟得上；想改内容就以它为基础做自己的版本
- **群组空间与收到的分享一个样**：两个区用同一套卡片和版式——同样的封面、标题、一行介绍、来源小字和打开方式，来回切换不用重新适应。差别只在规矩上：收到的分享要点“保存”选好目录才进自己的库，群组空间里的东西不用保存、打开就能用（也可以再存进我的库），卡片上标明来源、主按钮各取所需
- **详情、预览与正式演示分开**：单击条目只选定，双击 / 打开先进入**条目详情**（逐页缩略图、当前解析版本与来源、维护人 / 修改记录、讲稿、导出与分享）；整稿页面流只叫**预览 / 讲稿视图**，供浏览核对，不冒充正式演示。点详情里的**开始演示**或卡片上的**直接演示**，系统先按当前解析结果物化完整 PPTX，再由 **DeckCraft 承担全屏放映**：观众屏只有当前幻灯片，演讲者视图另有下一页、讲稿、计时与页码。DeckCraft 不可用时会明示并让用户改选 PowerPoint 放映或静态预览，说明动画 / 切换效果可能不同，绝不静默降级
- **离线缓存（只缓存我用过的）**：离线能力只覆盖**我的库**——广场里只看过、没拉入的稿不存完整内容。缓存的是你实际采用那一刻的一整套版本快照，历史版本和没用过的形态不预下载。触发不折腾人：第一次真正用一套稿（演示、导出、以 DeckCraft / PowerPoint 打开）时只问一次，要不要“自动缓存我用过的稿件”；开启后，实际用过的稿在后台自动缓存（有进度、可取消），只拉入、只看详情不触发；没开启就只能逐条手动“缓存到本地”。每条可移除缓存、设“常驻本地”免于容量淘汰、或加入“不要缓存”名单。断网时已缓存的稿能看详情、讲稿并用 DeckCraft 放映，会明确标着缓存版本，不冒充最新；联网同步成功后才换新快照。管理员可按组织 / 分组把策略设为仅手动或禁止缓存（客户专属等敏感内容常用），**管理员的更严格策略优先**；权限被撤销、条目被撤回或移出我的库的缓存，联网校验后会被清除。**缓存的落点分三层**：单条的状态和操作就在我的库卡片上（离线可用标、版本与大小小字，缓存 / 移除 / 常驻随手可点）；本地到底存了哪些稿、占了多少空间，去**内容页的「本地缓存」**里集中看、集中管；总开关、容量上限和管理员策略只在设置页
- **四个子区是切换进入的**：演示厅打开默认是广场，广场、我的库、收到的分享、群组空间靠切换进入、整页替换——不另设一个把四区各摆一行的货架主页，同一份稿只在自己区里出现一次，不双份展示，也不另设汇总我维护条目的区域
- **版式**：条目是图形为主的紧凑卡片网格（封面 + 标题 + 一行介绍 + 维护人小字），多个并排，不是一条占一行。你自己维护的条目卡片带一圈**绿色外框**，在哪个区都能一眼认出（这处绿色只表示“我维护的”，和索引页按公开范围给边框上色不是一回事）；演示厅不再另设「我维护的」汇总区——你维护的条目就在它所属的区里、靠绿框认，不重复汇总展示（索引页沉底的「我的未公开」是另一回事，那个保留）

## 五、设计方的补充建议（已于 2026-11-14 全部采纳并写入规格 v2.1 正文，下表为采纳对照）

1. **分发台账与版本分布（强建议）**：服务端能看到每份导出稿在谁手里、停在哪个索引修订、落后几条更新，可一键提醒未更新的人。大公司最常见的事故是“有人拿着三个月前的稿子在对外讲”，这项是治本的
2. **导出前体检（强建议）**：导出前自动过一遍清单——混入其他客户专属页、引用了内容已过期的形态、用了锁定版本、缺目标机器字体——逐项列出并让导出人确认，比事后出事故便宜得多
3. **主索引变更审核（建议）**：官方成稿（主索引）是公司的标准说法，建议它的增删条目需部门管理员确认后生效；普通页库发布不加此关，免得拖慢日常更新
4. **定时备份与一键恢复（建议）**：主机管理已有手动备份导出，建议补自动定时备份 + 在新机器上一键恢复并校验，与“数据目录可搬移”正好配套
5. **附件文字进搜索（建议）**：上传 Word / PDF 时抽取文字入索引，让介绍材料也能被全文搜到，而不只是挂着
6. **讲稿随版本**：（已采纳，见功能 7“讲稿与自动备注”）

**第二轮补充建议（2026-11-14 全产品复盘时提出，按“晚定代价”排序）**

7. **版本紧急撤回（动工前定）**：已发布的某个版本被发现数据错误时，作者 / 管理员可将其“撤回”：持有该版本的文稿下次打开收到强提示并指引换到指定替代版本。索引有作废，版本也应有撤回——版本状态机现在加一个状态是零成本，上线后再补要改数据
8. **授权有效期 / 临时授权（动工前定）**：跨部门项目借内容、借人时，授权可设到期日，到期自动失效。现在加一个字段的事，事后补要动整套权限查询
9. **存储保留策略（动工前定）**：只存片段 + 版本永不删 = 数据只增不减。先定：草稿过期自动清、已发布版本永久留但可归档、媒体文件按哈希去重存储、主机磁盘用量预警
10. **并发规则（动工前定）**：两人同时编辑同一索引、同时发布同一内容位时的规则（乐观锁：后提交者被提示基于最新重做），写成明文，免得上线后撞车
11. **离线降级规则（动工前定）**：服务器连不上时（出差、在家打开 PPT）：不查更新、文件照常可用、客户端可看缓存库。规则先写死，同事才不会被卡住
12. **备份升为一期必备（因不存原稿的新决策）**：服务器数据目录现在是全公司 PPT 资产的唯一副本——定时自动备份 + 备份到另一台设备 + 定期恢复验证，应从可选变为必做（强化第 4 条）
13. **字体治理（并入第 2 条体检）**：片段入库时记录所用字体；组装字体大杂烩、接收方缺字体是拼稿第一翻车点，体检报警 + 公司标准字体清单
14. **消息中心（功能级）**：维护人的待办集中一处——内容待更新、译文待同步、被请评审、版本被撤回涉及自己——不只靠打开 PPT 时才发现
15. **草稿评审评论（功能级）**：版本发布前可在其上留言讨论（谁看过、要改哪），大公司内容过审的留痕方式；简单文本评论即可
16. **可晚定的一组**：离职交接一键转维护人；全量数据导出（CLI 一条命令打包全部片段 + 元数据，防被自家系统锁死）；图片内文字 OCR 进搜索；企业微信 / 邮件通知打通
