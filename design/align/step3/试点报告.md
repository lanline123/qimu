# 第 3 步 · DeckCraft 渲染试点报告（2026-11-15）

方法：`tools/pilot_deckcraft_render.py`——同一稿件两条管线逐页对比。
LO 管线按试点时的服务端旧实现运行（soffice → PDF → pdftoppm -r 55）；
DeckCraft 管线为 `deckcraft-cli render --all --scale 1.0`，输出缩放至
LO 页尺寸后用 PIL 逐像素比（mean abs diff 0–255；hot_frac = 最大通道
差 >32 的像素占比）。原始数据见同目录 report.json。

## 目视抽查

- Redwood p8（表格页）：版式、配色、表格、页脚与 LO 几乎一致，标题字
  体度量略有差异（两个渲染器都只是 PowerPoint 的近似，LO 同样如此）。
- Case2 p2（柱状图，见同目录对照图）：数据、柱高、颜色、坐标标签全对；
  差异在图表标题位置（DC 靠左上、LO 居中）与网格线深浅——内容完整、
  构图偏移，属已知差距，缩略图用途（封面/卡片）下可接受。

## 结论：达标，已切换

本节记录试点时的切换方案。当前服务端仅用 DeckCraft 渲染缩略图，失败直接返回错误。缩略图使用 `thumbs/deckcraft-v2/` 重新缓存。

- 服务端缩略图默认改走 DeckCraft（`render_thumbs_deckcraft`，经
  deckcraft-cli 子进程，与现行外部渲染器架构一致，不把 DeckCraft 的
  依赖树链进 server 二进制）；二进制解析序：$QIMU_DECKCRAFT_CLI →
  server 同目录 deckcraft-cli → PATH。
- 回退双保险：QIMU_THUMB_RENDERER=libreoffice 全局钉回旧管线；
  DeckCraft 单次渲染失败自动回退 LO 并打日志。缓存按渲染器分目录
  （thumbs/deckcraft/ 与 thumbs/libreoffice/），切换不串图。
- E2E 实证（临时服务器 8736，Case2 版本 7 页）：DC 模式 720×405
  （--scale 0.75）；LO 模式 734×413；DC 二进制缺失时日志记录回退且
  LO 图正常返回。小瑕疵：回退产生的 LO 图仍存入当前所选渲染器的
  缓存命名空间（图本身有效，仅来源标注不精确）。
- 部署注意：打包分发时需把 deckcraft-cli 与 qimu-server 放同目录
  （或设 QIMU_DECKCRAFT_CLI），否则自动回退 LO（功能无损、速度回到
  旧水平）。DeckCraft 全屏演示接入不在本步范围（台账原定演示呈现
  随后续步/独立评估）。
