# 启幕 HTML 原型界面盘点

基准为仓库根目录的 [启幕原型-内容索引页.html](../启幕原型-内容索引页.html)。底栏有 9 个顶层编号（演示厅占 4 个），源码另有 25 个 `data-page` 容器和 3 个原生 `dialog`。全屏放映的观众和演讲者模式共用一个容器。索引子页、内容块下钻和内联面板另列。同一个界面的不同示例数据只计一次。

## 主窗口和业务页面

| 原型入口 | 界面及状态 | Rust 对照 |
|---|---|---|
| 共用框架 | 标题栏、菜单、图标工具栏、搜索、侧栏、底栏页号、消息、主题 | 标题、菜单、导航图标和索引底栏已做样板。全局搜索、消息、主题与各页工具状态待逐项比对 |
| #1 主页 | 左侧导航与快捷动作、欢迎区、四个启动动作、最近使用列表、空列表、无搜索结果 | `page_home`、`home_action_card`、模板选择。首轮对齐涵盖主页导航、动作布局、最近记录与搜索 |
| #2 演示厅 · 公共 | 分类目录、公共成品卡片、待审入口和空状态 | `sr_nav_body`、`sr_main_body`、`review_detail_body`，待对齐 |
| #3 演示厅 · 我的 | 自定义目录、个人组装、保存的共享稿件、离线状态 | `ShowroomState`、演示厅个人库及本机缓存，待对齐 |
| #4 演示厅 · 分享 | 收件、待保存、粘贴链接、发送者与共享范围 | 演示厅收件区域，逐项核对入口及数据 |
| #5 演示厅 · 群组 | 群组目录、成员信息、共享的索引与成品、空状态 | 演示厅群组区域，逐项核对成员管理及共享入口 |
| 演示厅详情 | 封面、逐页缩略图、逐页讲稿、听众放映、演讲者视图、单页编辑 | `SrFrame::Deck`、`PresentState`、`PageEditState`，待对齐 |
| #6 页面 · 目录 | 目录树、内容卡片、选中态、卡片筛选、目录空态、本地缓存列表 | `ct_nav_body`、`ct_main_body`，待对齐 |
| 内容块下钻 | 内容块与递归子块、语言形态、当前及历史版本、附件、讲稿、绑定、原位替换、当前选区、选页 | `ContentFrame`、`unit_detail`、选页模式及版本相关操作，待对齐 |
| #7 索引总览 | 按目录分组、按关系查看、使用中／历史／全部筛选、范围色标、我的索引、自维护 | 总览网格和单击／双击流程已做样板。分组、关系视图和筛选仍待核对 |
| #7 索引详情 | 图墙、提交图、历史版本、导出记录、派生关系、分支和版本命令、目录、条目选页、插入和调整顺序 | 图墙首轮对齐。现有提交历史与导出记录需按原型整理为分视图，派生关系待核对 |
| 新建索引 | 选取内容块、设置索引名和目录、创建后进入详情 | `IndexFrame::Create`，待对齐 |
| #8 设置 | 个人资料、公司设置、组织管理、待审队列和审批详情，按角色显示 | `settings_sections`、`st_main_body`、审批详情。客户端另有服务器、内容组授权、语言、AI、缓存等实际配置 |
| #9 回收站 | 分类目录、列表、单项和批量还原、清空、详情预览、空状态 | `TrashFrame::List`、`TrashFrame::Preview`、确认层，待对齐 |

## 整页流程和对话框

以下是 HTML 容器清单。整页流程由原型的 `pageHost` 承载，编号为 401 起或由演示厅稿件与模式计算。

| 归属 | HTML 容器及标题 | Rust 对照 |
|---|---|---|
| 内容发布 | `pubDlg` 发布新版本、`draftDlg` 原位替换、`pasteDlg` 粘贴发布、`rejDlg` 驳回详情 | 有发布、粘贴、审批及版本更新流程。需核对各自入口、表单和回退 |
| 内容查看 | `lightDlg` 大图预览、`craftDlg` 内嵌编辑预览 | 有预览层及编辑路径。内嵌预览的功能范围待核对 |
| 索引编辑 | `idxPickDlg` 插入条目选块、`mergeDlg` 条目级三方合并、`pushChkDlg` 推送到演示厅 | 有内容页选块、分支合并及推送操作，交互位置和整页布局待对齐 |
| 演示与编辑 | `showDetailDlg` 稿件详情、`presentDlg` 讲稿预览、`playDlg` 放映和演讲者模式、`deckEditDlg` 编辑当前页、`saveAskDlg` 未保存修改确认 | 有详情帧、放映、编辑和确认层，逐项验收 |
| 保存和共享 | `pullDlg` 收进我的、`shareDlg` 分享、`submitDlg` 自荐公开、`applyDlg` 申请公开、`pasteLinkDlg` 粘贴链接、`contactsDlg` 添加联系人 | 核对保存到库、共享与审核的现有服务端能力，再对齐表单和选择器 |
| 群组与组织 | `groupDlg` 新建群组、`inviteDlg` 邀请成员、`shareIntoDlg` 分享到群组、`orgPickDlg` 组织添加成员 | 群组与组织管理有对应业务，入口和交互待核对 |
| 通知 | `msgDlg` 消息中心 | 当前有操作提示，独立消息中心待核对 |
| 原生对话框 | `bindConfirmDlg` 移动绑定确认、`cacheAskDlg` 自动缓存确认、`qvAllDlg` 全部历史版本 | 逐项核对确认路径、历史层与数据状态 |

HTML 还包括 `idxReplaceDlg` 条目替换面板、`deriveDock` 派生速览、`cachePop` 清除缓存确认、工具栏更多菜单以及目录行菜单。这些随对应页面对齐。登录窗口、PDF 预览、文件选择和回收站销毁确认属于 Rust 客户端的现有流程，也纳入回归验证。

## 验收顺序

1. 主窗口和主页。
2. 演示厅四区、稿件详情、讲稿、两种放映模式及页编辑。
3. 页面目录、内容块和子块、历史版本、语言绑定、发布及缓存。
4. 回补索引的分组、筛选、详情分视图和新建流程。
5. 设置、组织审批、回收站和剩余确认层。

每屏先用同数据、同主题、同窗口尺寸对照 HTML 和 Rust。记录入口、布局、空态、选中态以及真正执行的动作。桌面端按 Windows、macOS、Linux 分别核对窗口、字体和缩放。原型里只用模拟数据支撑的交互，先核对启幕现有 API 和数据状态再实现。
