# 启幕客户端 · 视觉对齐清单

目标：真客户端（egui）逐页与 FigCraft 设计稿（`qimu-ui.figcraft` 六板，1440×900）一致。
方法：同尺寸 1440×900、同数据（dev 库 Redwood 种子）截图，板图采样色值/量坐标比对。
基线截图：`design/align/before/`；对齐后：`design/align/after/`。

## 迭代记录

- 第 0 轮（基线）：before 六图存 `design/align/before/`，差异如上表。
- 第 1 轮（骨架与令牌）：顶栏 52/#1F1F1F/logo 方块/盒装右按钮；侧栏 exact_width 定宽
  （220/208）+ 整行 tree_row 选中态；CentralPanel 去统一边距、各页 body_frame（左 24/上 10）；
  登录按板重做（500 卡、logo 块、330×34 字段、胶囊按钮）；演示厅卡 340×300 + 文字动作行；
  内容页工具行（搜索 placeholder/文字动作/创建盒装按钮）；总览卡内距；详情头（分支 96 宽、
  发布蓝胶囊、动作文字化、新分支名框缩至 110）、条目卡内边距 16/10/12、去竖分隔线；
  设置导航整行、表单 380×34/pitch 54、补姓名行、保存按钮移入字段列、新增个人绑定预览卡；
  card_frame 去阴影；控件圆角 r8；滚动条改浮动细条。截图存 align/r1/。
- 第 2 轮（定位三处系统性偏差）：① 卡片正文继承了网格的 16px item_spacing（子 Ui 继承父
  spacing）——三类卡正文内重置 (8,5)，卡高/行距应声收紧；② 滚动条亮色源于 ScrollStyle
  默认 foreground_color=true——改 false + 静止背景透明；③ 登录卡上距校准至 225（与板一致）、
  详情头逐行压缩。截图存 align/r2/。
- 第 3 轮（收尾）：详情头再压缩（返回行紧凑 scope、分支名框 margin、空距）——首卡 218→199
  （板 191）；登录/资料字段加 margin(10,8) 使文字垂直居中。终版截图存 align/after/。
  终测关键值：顶栏 #1F1F1F/52 ✅；内容左缘 x=244 ✅；登录卡顶 225（板 226）✅；
  设置字段 pitch 54、高 34、首字段 y=113（板 116）✅；条目卡高 194（板 194）✅、pitch 238（板 234）；
  总览卡顶 114（板 110）、卡高 ≈293（板 284，余差见下）。

## 已知不可完全一致项（如实记录）

- 底部状态栏：板图无此栏；客户端的操作反馈（msg）只在此显示，删除即丢功能反馈。
  处理：保留但弱化——与画布同色 #121212、无描边、11px 弱文字，视觉上并入画布。
- 搜索框圆角：egui 0.29 TextEdit 圆角取全局控件圆角（r8），做不到板图的 r16 胶囊（除非自绘输入框）。
- 板图缩略图为示意色块，实机为真实幻灯片渲染图，内容不同属正常。
- 索引总览标题：板图是选中「公司介绍」时的形态（标题=文件夹名）；实机默认「全部」时标题为「全部索引」，属数据状态差异，非布局差异。
- 字体行距差异（总览卡高 +9、详情首卡 +8 的主因）：egui 用内嵌普惠体的字体度量排版，
  label 文字墨迹在行框内比 FigCraft 的文本框低约 10–14px，每多一行文字累积数 px。
  全局改字体 y 偏移会让手工居中绘制的 chip/按钮文字错位，得不偿失，故保留并在此明示。
- 设置个人绑定预览位置：随表单横向流式排布（x≈765），板图为固定 x=800；差 35px，
  源于实机表单列宽由最长标签（微信二维码）决定，与板图手画列宽不同。
